# LiveEdit

같은 사설망(회사 내부망/VPN)에 있는 팀원끼리, 노션처럼 Obsidian 노트를 실시간으로
같이 보고 편집하는 플러그인입니다. 동시 본문 수정은 CRDT(Yjs)로 병합합니다.

플러그인 설정에는 **방장 / 참여자** 역할 구분이 있습니다. 방장은 `server/`의
릴레이 서버를 자기 PC(또는 팀 상시 서버)에서 계속 켜두고 Obsidian도 함께 켜서
같이 편집하는 사람이고, 참여자는 방장이 알려준 서버 주소로 접속만 하면 됩니다.
방장은 서버의 별도 인증 키로 인증하며 참여자 퇴장과 신규 입장 잠금을 관리합니다.
문서 내용은 CRDT로 대등하게 병합됩니다. 새 방의 초기 문서는 방장의 공유 폴더에서 가져옵니다.

개별 계정 로그인과 첨부파일/캔버스 동기화는 제공하지 않습니다. 공유 접속 토큰과
별도의 방장 인증 키를 지원합니다. `ws://`는 평문 연결이며 TLS는 별도로 구성해야 합니다.

## 0.5.1 공유 폴더 읽기 전용

- 공유 폴더를 반드시 지정합니다. 개인 노트는 그 밖에 보관하세요.
- 플러그인 활성화 중 연결이 끊긴 것으로 감지되거나 최신 문서를 받는 동안에는 공유 노트가 읽기 전용입니다.
  입력·붙여넣기·되돌리기와 Obsidian의 공유 파일 생성·수정·삭제·이름 변경을 막습니다.
- 서버 연결 후 본문·파일 목록과 대기 중인 디스크 저장을 반영한 뒤 편집을 허용합니다.
  파일 저장에 실패하면 편집 잠금을 해제하지 않습니다.
- 공유 폴더 밖의 개인 노트는 연결 상태와 관계없이 편집할 수 있습니다.
- 플러그인을 끄거나 외부 프로그램으로 파일을 바꾸는 것은 운영체제 수준에서 차단하지 않습니다.
  그런 로컬 변경은 참여자 재접속 때 백업 후 최신 공용 상태로 맞춥니다.
- 서버는 0.5.0과 호환됩니다. 모든 사용자의 플러그인은 0.5.1로 업데이트하세요.

## 0.5.0 동기화·재접속 수정

모든 참여자는 본문 편집·파일 생성·이름 변경·삭제를 함께 수행합니다.
방장 역할은 참여자 관리와 새 방 초기 문서 제공에 사용합니다.

- 설정에 **접속 / 재접속 / 연결 해제** 버튼을 추가했습니다. 연결 중에는 중복 접속을 막습니다.
- 참여자는 자동·수동 재접속 모두 새 문서 상태로 접속합니다. 오프라인 변경을 서버에 재병합하지 않고,
  방장이 서버에 반영한 최신 공용 문서 내용과 파일 목록을 받아옵니다.
- 참여자의 공유 범위 안에만 있는 로컬 노트는 백업 후 휴지통으로 이동합니다. 로컬에서 지운 공용 노트는 다시 생성합니다.
  내용이 다른 파일과 아직 저장하지 않은 편집기 본문도 `.liveedit-backups/`에 보관합니다.
- 이름 변경은 동일한 공유 본문의 경로만 바꾸므로 동시에 들어온 편집이 끊기지 않습니다.
- 생성 중 삭제된 파일의 뒤늦은 읽기 결과가 파일을 다시 만들지 않도록 했습니다.
- 동시에 같은 경로를 만들거나 바꿀 때는 모든 클라이언트가 동일하게 경로를 선택하며,
  교체·삭제 전 본문 사본을 백업합니다. 삭제와 동일 문서 편집이 겹치면 삭제된 상태로 수렴합니다.
- 지속 편집 중에도 서버가 주기적으로 저장하고, 저장 실패한 빈 방은 메모리에서 바로 버리지 않습니다.
- 0.4.1의 노트 전환 오염과 지연된 파일 읽기의 덮어쓰기 수정도 포함합니다.

## 업데이트 적용

**서버와 모든 플러그인을 함께 0.5.0 이상으로 업데이트하세요.** 이름 변경 데이터 구조가 바뀌어
이전 플러그인은 새 서버에서 접속을 거절합니다. 기존 서버 저장 데이터는 새 서버가 읽을 수 있습니다.

1. 기존 노트와 서버 데이터를 백업합니다.
2. 루트에서 `npm ci`와 `npm run build`를 실행합니다.
3. Obsidian vault의 `.obsidian/plugins/liveedit/`에 `main.js`, `manifest.json`, `styles.css`를 복사하고 플러그인을 다시 켭니다.
4. `server/`에서 `npm ci`, `npm run build` 후 아래 환경변수를 설정하고 서버를 실행합니다.
5. 방장 플러그인 설정에 동일한 **방장 인증 키**를 입력합니다. 새 방은 방장이 먼저 접속하세요.

PowerShell 실행 예:

```powershell
cd server
$env:LIVEEDIT_TOKEN = "팀원에게-공유할-충분히-긴-랜덤값"
$env:LIVEEDIT_HOST_TOKEN = "방장만-보관할-별도의-충분히-긴-랜덤값"
$env:LIVEEDIT_DATA_DIR = Join-Path $PWD "data"
node dist/server.js
```

팀원 서버 주소는 `ws://사설IP:1234?token=팀접속토큰`으로 입력합니다.
방장 키는 주소에 직접 넣지 말고 플러그인의 전용 설정에 입력하세요.
방장 키를 아는 사람은 해당 서버의 모든 방을 관리할 수 있습니다.

검증: 루트의 `npm test`는 로컬 임시 서버로 편집 병합, 자동 재연결, 권한 제한,
입장 잠금, 퇴장, 연결 유지, 디스크 복구와 파일 동기화 범위를 확인합니다.
실제 CodeMirror 편집기와 파일 이벤트를 흉내 낸 vault를 사용하며, 세 참여자의 동시 파일 작업을
역순으로 전달해 문서·디스크가 수렴하는지도 확인합니다. 실제 Obsidian 사설망 장기 사용 검증과는 구분합니다.

> 팀원이 설치·사용하는 방법만 필요하다면 **[docs/사용법.md](docs/사용법.md)** 를 보내주세요.
> 이 README는 서버 운영/빌드/배포를 맡는 사람을 위한 문서입니다.

## 구성

- `server/` — 팀 내부망에 상시로 띄워두는 아주 작은 릴레이 서버 (Node.js)
- `src/` — Obsidian 플러그인 소스 (빌드하면 저장소 루트에 `main.js`가 생성됨)

## 1. 릴레이 서버 띄우기

```bash
cd server
npm install
npm run build
node dist/server.js
```

기본 포트는 `1234`입니다. 포트나 접속 토큰을 바꾸고 싶을 때만 환경변수를 설정하면
되는데, 셸마다 문법이 달라서 아래 중 본인 환경에 맞는 걸 쓰세요.

- **Windows cmd.exe**
  ```bat
  set PORT=1234
  set LIVEEDIT_TOKEN=팀비밀값
  node dist/server.js
  ```
  (한 줄로 하려면: `set PORT=1234 && node dist/server.js` — `PORT=1234 node ...`처럼
  유닉스식으로 쓰면 "내부 또는 외부 명령이 아닙니다" 오류가 납니다)

- **Windows PowerShell**
  ```powershell
  $env:PORT = "1234"
  $env:LIVEEDIT_TOKEN = "팀비밀값"
  node dist/server.js
  ```

- **macOS / Linux / Git Bash**
  ```bash
  PORT=1234 LIVEEDIT_TOKEN=팀비밀값 node dist/server.js
  ```

환경변수 설명:
- `PORT` (기본 1234): 리슨 포트
- `LIVEEDIT_TOKEN` (선택): 팀 접속 토큰. 설정하지 않으면 해당 네트워크에서 누구나 접속할 수 있습니다.
- `LIVEEDIT_HOST_TOKEN`: 방장 관리 기능의 인증 키. 팀 접속 토큰과 다른 값을 사용합니다.
- `LIVEEDIT_DATA_DIR` (기본 `./data`, 서버 실행 폴더 기준): 방 데이터를 보관할 폴더. 재시작 시 같은 경로를 사용하고 이 폴더를 백업하세요.
- 상태 확인: `GET http://서버주소:포트/healthz`

사내 서버나 팀원 PC 등 항상 켜져 있는 곳에 올려두고, 팀원들에게 `ws://내부IP:포트`
주소만 공유하면 됩니다. (터미널을 닫으면 서버도 같이 꺼지니, 계속 띄워두려면
Windows에서는 [PM2](https://pm2.keymetrics.io/) 같은 프로세스 매니저나 작업 스케줄러
활용을 추천합니다.)

## 2. 플러그인 설치 (BRAT)

1. Obsidian 커뮤니티 플러그인에서 **BRAT**(Obsidian42 - BRAT) 설치 후 활성화
2. BRAT 설정 → `Add Beta plugin` → 저장소 경로에 `<깃허브아이디>/liveedit` 입력
3. 설치 후 커뮤니티 플러그인 목록에서 **LiveEdit** 활성화

> BRAT는 GitHub Release에 첨부된 `main.js` / `manifest.json` / `styles.css`를 내려받습니다.
> 이 저장소는 태그를 push하면 (`.github/workflows/release.yml`) 자동으로 릴리즈를
> 만들고 세 파일을 첨부하도록 되어 있습니다. 새 버전을 배포하려면:
>
> ```bash
> npm version patch   # package.json/manifest.json/versions.json 버전 동기화
> git push --follow-tags
> ```

## 3. 설정

플러그인 설정 탭에서:

- **이 PC의 역할**: 방장 / 참여자. 방장은 서버 인증 키가 있어야 접속할 수 있습니다.
- **방장 인증 키**: 서버의 `LIVEEDIT_HOST_TOKEN`과 동일한 값. 플러그인 설정 파일에 저장됩니다.
- **릴레이 서버 주소**: 방장은 보통 `ws://localhost:포트`, 참여자는 방장에게 받은
  사설망 주소(예: `ws://192.168.0.10:1234`)를 입력. 방장 모드에서는 옆에
  **서버 상태 확인** 버튼이 나타나 서버가 살아있는지 바로 확인할 수 있습니다.
- **방 코드**: 같은 코드를 쓰는 사람끼리만 같은 내용을 공유 (팀/프로젝트별로 다르게 써도 됨)
- **표시 이름 / 커서 색상**: 다른 팀원에게 보여지는 내 정보
- **공유 폴더**: 필수 항목. 예: `Team`. 연결·동기화 완료 전에는 읽기 전용이며 개인 노트는 그 밖에 둡니다.
- **자동 재연결**: 연결 끊기면 자동 재시도 + Obsidian 시작 시 자동 접속

## 4. 사용

명령 팔레트(Ctrl/Cmd+P)에서:

- `LiveEdit: 세션 연결`
- `LiveEdit: 세션 연결 해제`
- `LiveEdit: 참여자 보기`
- `LiveEdit: 서버 상태 확인 (방장용)` — 방장이 자기 서버가 살아있는지 바로 확인

상태바에 `🟢 LiveEdit(방장) · N명` 또는 `🟢 LiveEdit(참여자) · N명` 식으로 표시되고,
클릭하면 참여자 목록이 열립니다.

같은 노트를 동시에 열면 문자 단위로 실시간 반영되고, 서로 다른 노트를 보고 있어도
백그라운드에서 계속 최신 내용으로 동기화됩니다. 새 노트를 만들거나 지우면 팀원
vault에도 그대로 반영됩니다.

## 알려진 제한사항 (의도적으로 가볍게 유지)

- `.md` 파일만 동기화합니다 (이미지 등 첨부파일, `.canvas`는 대상 아님)
- `.md` 이름 변경은 본문 연결을 유지합니다. 빈 폴더만의 생성·삭제는 동기화 대상이 아닙니다.
- 서버는 변경 후 약 300ms에 방 상태를 디스크에 저장합니다. 갑작스러운 종료 시 마지막 저장 이후 변경분은 유실될 수 있습니다.
- 참여자 재접속은 공용 상태를 우선합니다. 오프라인 수정은 백업으로 남으며 자동 병합하지 않습니다.
  방장의 자동 재접속은 기존 문서의 미전송 변경을 병합합니다. 앱을 종료하면 아직 저장되지 않은 변경은 보장하지 않습니다.
- 최초 접속에서 서버와 내용이 다른 로컬 파일은 `.liveedit-backups/`에 복사한 뒤 서버 내용을 반영합니다. 원격 삭제는 로컬 휴지통으로 이동합니다.
- 방장 메뉴는 상태바 → 참여자 목록에서 사용할 수 있습니다. 퇴장은 현재 연결을 종료하고 자동 재접속을 멈추지만 영구 차단은 아닙니다.
- 신규 입장 잠금은 재접속도 막습니다. 서버 재시작 또는 빈 방 정리(5분) 후에는 잠금이 해제됩니다.
